# Token Saving Strategy & Tests

## 🚀 Strategy: Global Caching (Supabase)
We have upgraded to a **Supabase-Based Global Caching System**. This treats lesson content as a shared asset, allowing any user to benefit from lessons generated by others.

### Architecture
1.  **Storage**: Supabase Table `ai_content_cache`.
2.  **Logic**: 
    *   **AIService**: Checks Supabase before API calls.
    *   **Shared Economy**: One user pays for the generation; everyone else gets it for free.
    *   **TTL**: Cache expires after 30 days to ensure content updates.
    *   **Partial Caching**: `CEFRContentService` regenerates Quizzes on cache hits to keep practice fresh.

### Implemented Files
*   `src/services/AIService.js`: Supabase integration.
*   `src/services/CEFRContentService.js`: Partial caching logic.

## 🧪 Verification & Testing
The test script simulates API traffic to verify hits/misses.

### Test Script
*   **File**: `lang-learning-backend/tests/measureTokenSavings.js`
*   **Command**: `node lang-learning-backend/tests/measureTokenSavings.js`

### Results
*   **Performance**: ~100% Savings for shared lessons.
*   **Latency**: ~50ms Supabase query vs 3000ms AI generation.
*   **Scalability**: Persistent, server-independent cache.
